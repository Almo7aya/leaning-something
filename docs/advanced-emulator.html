Intro machine

Not a game. A fake 4K intro running on a teaching RISC, with the same boundaries as KytyPS5: two guest threads (raster + mixer), a GOT of NIDs, a TLS Call9 patch at boot, PM4 packets that only carry uniforms, and a shader cache that recompiles when those uniforms change shape. You twist knobs in guest memory. The intro is the side effect.

            What you are looking at
            
    
            
      The raster thread only stores a handful of uniforms and submits one fullscreen draw.
      The mixer thread writes an envelope into a tiny audio ring. Cold boot plays the loader
      pipeline back one stage at a time — reserve → map → relocate → TLS patch → protect →
      threads → entry — so you can watch the boundary the emulator actually crosses. Changing
      the effect changes the specialisation key, so the cache misses and the frame stalls
      while it walks Decode → CFG → Translate → Materialize → Compile — the same split as
      TranslateProgram / CompileProgram, and the same first-encounter
      stutter a real title shows. The Shader recompiler panel shows that program as it is
      built — the decoded RDNA 2 ISA, its control-flow graph, the typed IR, the
      resource table and the emitted SPIR-V — and the pace control (learn / normal /
      fast) slows the whole thing down so you can read each stage. Click any stage in either
      pipeline to open a live inspector (memory map, GOT, TLS bytes, PM4 register writes, the IR
      and SPIR-V…). The intros are uniforms visualised; Serpent, Breakout, Drift, Invaders, Flappy
      and Pong are real guest-ticked programs. Megademo links two dozen parts at boot and
      runs them back to back. Nebula Run ✦ is the big one — a simple space shooter whose
      background, ship, every enemy type, weapon, explosion and HUD is its own pipeline, compiled
      the first time it appears on screen (streaming shader compilation, in the background,
      so gameplay keeps running). Watch the Shader recompiler fill — click any cached
      pipeline to read its RDNA 2 → IR → SPIR-V — the Vulkan panel for the host
      vk* calls, and the Pipeline cache for the two levels the emulator keeps:
      an in-memory ProgramCache (L1) and the on-disk VkPipelineCache (L2). Flush L1 and
      the next draws rebuild pipelines straight from disk without recompiling SPIR-V; wipe the disk
      cache and everything compiles cold, exactly like a first run of a game.
