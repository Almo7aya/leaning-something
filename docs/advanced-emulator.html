Intro machine

Not a game. A fake 4K intro running on a teaching RISC, with the same boundaries as KytyPS5: two guest threads (raster + mixer), a GOT of NIDs, a TLS Call9 patch at boot, PM4 packets that only carry uniforms, and a shader cache that recompiles when those uniforms change shape. You twist knobs in guest memory. The intro is the side effect.

Separate program reuse from driver-cache help

Read first: The program cache. Return to the learning route.

Model boundary: A JavaScript interpreter drives a Canvas teaching model. Shader stages, Vulkan calls and disk-cache events are simulated; no native PS5 code or Vulkan compiler runs here.

  1. Prepare the experiment, wait for boot to finish, and use Step frame to request the initial effect. Let the displayed compilation finish, then step again.
  2. Flush L1 cache and request another frame. Observe translation and specialization phases reappear.
  3. Enable the simulated disk cache, warm it, flush L1 again, and repeat. Predict which work still has to happen.
Check your explanation

A live program hit can reuse the translated/specialized result. The simulated disk cache represents driver pipeline data: it can assist host pipeline creation but cannot replace guest shader translation after L1 is lost. Its contents exist only in this page’s JavaScript state and can survive the model’s reboot, not a browser reload.

            What you are looking at
            
    
            
      This page executes an invented guest ISA in JavaScript. A raster thread updates uniforms
      and submits teaching packets; a mixer thread writes an audio envelope. The Canvas renderer
      draws the result. Click the display before using game keys. Run, Step frame and Step insn
      let you choose when execution advances; Cold reboot restores the teaching machine.
    
            
    
            
      The loader and shader pipelines are explanations of KytyPS5 boundaries. Their RDNA2, IR,
      SPIR-V and Vulkan panels contain illustrative text and simulated events. Changing an effect
      or specialization can trigger a simulated compilation delay. The pace control slows those
      stages so you can inspect the memory map, GOT, TLS bytes and resource state. These timings
      do not measure the native emulator or your GPU.
    
            
    
            
      The game scenes, Megademo and Nebula Run provide different workloads for the same model.
      Nebula Run queues simulated background compilation as new effects appear. The L1 cache
      represents reusable program results; the simulated driver cache represents help with host
      pipeline creation. Flush L1 to request translation again. Wipe the driver cache to remove
      that modeled assistance. Both caches live in this page’s memory; only the simulated driver
      cache survives Cold reboot, and neither persists across a browser reload.
