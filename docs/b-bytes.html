Before you start

The same value in three notations

A bit is 0 or 1; an eight-bit byte represents values 0 through 255. Decimal uses ten digits, binary two, hexadecimal sixteen. Thus 15 == 0b1111 == 0x0f. A hexadecimal digit represents four bits, so two digits represent a byte. std::uint32_t is an unsigned 32-bit integer on the platforms used here. std::size_t is the unsigned type used for object sizes and indices; its width depends on the platform.

value >> 8 shifts a value right by eight bits. & 0xffu keeps its lowest eight bits. | combines bit fields; |= combines into the variable on its left. The u suffix makes a literal unsigned. Keep shift counts below the width of the shifted type; our loop uses only 0, 8, 16 and 24.

Bytes have an order

The bytes 78 56 34 12 encode 0x12345678 in little-endian order: the least significant byte comes first. The explicit shifts below decode that order regardless of the host's byte order. An offset is a position within this buffer, not an absolute memory address.

std::span<const std::uint8_t> passes a read-only view of bytes and their count without copying them. B3 explains its lifetime. std::optional<T> contains either a value or no value. Check it before using *value; std::nullopt reports that no result exists.

Check a range before using it

A five-byte buffer has valid indices [0, 5): include zero, exclude five. A four-byte read at offset 1 ends exactly at 5 and is valid; a read at 2 is truncated. First reject an offset larger than the size, then check the remaining byte count. This avoids an overflowing offset + 4 calculation. || means logical OR and evaluates its right side only when the left side is false, so the subtraction happens only after the offset check succeeds.

Complete runnable teaching program · bytes.cpp

#include <array>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <limits>
#include <optional>
#include <span>

// Teaching format: four little-endian bytes, not an ELF or PM4 parser.
std::optional<std::uint32_t> read_u32(std::span<const std::uint8_t> bytes,
                                     std::size_t offset) {
    if (offset > bytes.size() || bytes.size() - offset < 4) {
        return std::nullopt;
    }
    std::uint32_t value = 0;
    for (std::size_t i = 0; i < 4; ++i) {
        value |= std::uint32_t{bytes[offset + i]} << (8 * i);
    }
    return value;
}

int main() {
    const std::array<std::uint8_t, 5> bytes{0x78, 0x56, 0x34, 0x12, 0xff};
    const auto value = read_u32(bytes, 0);
    if (!value || *value != 0x12345678u) return 1;
    std::cout << "word=0x" << std::hex << *value << '\n';
    std::cout << "field=0x" << ((*value >> 8) & 0xffu) << '\n';
    const auto last = read_u32(bytes, 1);
    if (!last || *last != 0xff123456u) return 1;
    if (read_u32(bytes, 2) || read_u32(bytes, bytes.size()) ||
        read_u32(bytes, std::numeric_limits<std::size_t>::max()) ||
        read_u32({}, 0)) return 1;
    std::cout << "last valid offset=1\n";
    std::cout << "truncated, end, huge and empty reads rejected\n";
}

Exercise

Predict the result at offset 1. Then change the first byte from 0x78 to 0x79. Which output and checks should change? Explain why offset 1 is unaffected. Finally design a two-byte reader on paper: specify its return type, length check and shifts before coding it.

Hint

At offset 1 the selected bytes are 56 34 12 ff. The first byte of the entire buffer is not part of that range.

Worked answer and rubric

Offset 1 produces 0xff123456. Changing byte 0 makes the first word 0x12345679; its field at bits 8–15 remains 0x56. A two-byte reader checks remaining size against 2 and combines shifts of 0 and 8. Test empty input, exactly two bytes, a last-valid offset, a truncated range and a huge offset. You are ready when you can justify the guard before discussing the decoding loop.
