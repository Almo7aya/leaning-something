How a PlayStation 5 emulator works

KytyPS5 runs PS5 games on a PC. Not by simulating a console — by impersonating one: the game's own code executes natively on your CPU while the emulator forges an operating system and a GPU underneath it. This takes that apart until you could change it yourself.

Current-source checkpoint

This includes the two-stage shader recompiler (translate once, compile per resource snapshot), mesh-shader geometry stages, the slimmer pipeline key, the cross-vendor TLS patch, the DualSense HIDAPI input path and the sixteen-executable regression suite. The shape of it

Guest

A game module is an ELF no normal loader accepts. It imports functions by NID — short encoded ids, not names.

Kyty

The runtime linker resolves those ids against hand-written implementations, rewrites a few instructions, and jumps in.

Host

From there the code runs natively. There is no interpreter. The work is faking an OS and a GPU around it.

The GPU half is the harder half. The game writes PM4 command packets into a ring buffer; a software command processor decodes them, turns accumulated register writes into Vulkan pipeline state, and translates compiled RDNA 2 shader binaries into SPIR-V. All the while CPU and GPU share memory each believes it owns, and coherency is held together by catching host page faults — with the guest convinced pages are 16 KB and the host insisting they are 4 KB.

What you'll be able to do

  • 02Open a game module and see exactly what the runtime linker sees: the Sony segments, the dynamic tags, the imports it can't resolve.
  • 03Implement a missing HLE function and watch a title get further than it did before.
  • 04Explain why a shader fell back to the dispatcher, and what would have to change for it not to.
  • 05Read a failing log and tell the difference between a cause and a symptom.
