What makes this run inspectable?

State, not an animated script

A deterministic interpreter executes a stored bytecode. A bounded compiler lowers three real RDNA ALU encodings into operations that the software vertex executor consumes. A barycentric rasterizer computes the actual image. Every recorded event contains a snapshot you can revisit.

The model has explicit edges

The instruction set, import IDs, scheduling, state-slot meaning and cache capacity are teaching choices. ELF and PM4 header decoding use the Playground readers. The shader subset is tiny; it is not a complete RDNA implementation. There is no PS5 binary execution, Vulkan, real thread contention, or native performance measurement.

Evidence you can carry away

Export the configuration, ordered events, memory writes and checks. Import re-executes the configuration and verifies the evidence. The fingerprint detects accidental mismatch; it is not a cryptographic signature. Files are processed locally. A view link shares configuration and event position, not uploaded data.

Follow the matching source from each selected event, then return to the native draw walkthrough. Use Playground to inspect artifacts from a real KytyPS5 run. Use the browser micro-emulator for a continuous playable guest.
