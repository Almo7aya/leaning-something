Shaders: RDNA 2 → SPIR-V

Games ship compiled RDNA 2 shader binaries. Vulkan wants SPIR-V. Translating the arithmetic is mechanical; recovering structured control flow from an unstructured branch soup is the actual problem, and the reason this is the largest single piece of the emulator.

Read

At main commit 5b7d334 (18 September 2026), the recompiler is about 29,300 lines across 84 files under recompiler/. It is organised as an explicit compiler pipeline: frontend/decode, frontend/cfg, frontend/translate, a typed value IR and its passes, then backend/spirv.

How to read the recompiler

TranslateProgram() builds a typed IR through encoding-family opcode dispatchers; SRT and resource analysis follow values in that IR. Failures EXIT. The pipeline is split so one translation can be specialised for many resource snapshots. Merged geometry stages compile as ShaderType::Mesh Vulkan mesh shaders.

Why it is hard, restated precisely

  • The input has no source-level structure. It is an instruction stream operating on scalar and vector registers, with no source variables or functions.
  • Control flow is hardware-shaped. Guest branches and execution masks must become SPIR-V selections and loops with declared merge and continue blocks.
  • Resources are computed values. A descriptor may be inline in user data or reached through shader resource-table loads, so binding requires tracing the shader's own address calculations.
  • Wave semantics differ. The guest assumes 32- or 64-lane waves and cross-lane operations; the host exposes Vulkan subgroups and their capabilities.
  • Failure can be visual only. A bad translation may draw the wrong pixels without crashing, which is why shader tests dominate the suite.

The current pipeline

Two functions in ShaderRecompiler.cpp are the authoritative reading map. TranslateProgram() runs once per shader binary and produces an immutable plan; CompileProgram() runs once per resource specialization and emits SPIR-V. Both log the expensive phases with the shader hash:

The current phasesclick a stage

With --shader-log-direction File, Kyty writes decoded, CFG/IR, and SPIR-V material under _Shaders/. The main log also records decode, CFG, translation, and emission timings with the shader hash.

Decode, recover control flow, translate

frontend/decode/ShaderDecoder.cpp turns variable-length encodings into typed instructions from the SOP, VOP, SMEM, buffer, image, FLAT, LDS, and export families. frontend/cfg/ShaderCFG.cpp splits those instructions into blocks, computes graph facts, detects irreducible regions, and attempts to recover the merge and continue blocks SPIR-V requires.

Irreducibility or a failed Structurize() is a supported outcome. Kyty restores the unstructured graph, sets dispatcher_fallback and records a fallback_reason; the SPIR-V backend then represents the shader as a loop around a program-counter dispatcher. This is slower, but it gives unsupported graph shapes an explicit fallback instead of silently miscompiling them. LogDispatcherFallback() prints the phase (build or structurize), the failure kind and the block, which is the line to grep for.

frontend/translate is a real frontend layer. Translate.cpp owns program setup while category files such as Scalar.cpp, Vector.cpp, and Memory.cpp dispatch decoded opcodes into typed IR operations. The opcode coverage grows almost daily; the September 2026 commits alone added buffer/image atomics (BUFFER_ATOMIC_CMPSWAP, the _X2 swap and OR variants, IMAGE_ATOMIC_SWAP), DPP row-xmask, conditional 64-bit scalar moves, V_CMP_LT_U64, S_FLBIT_I32_B32 and VOP3 FMAC source modifiers.

Merged geometry stages become mesh shaders

RDNA 2 runs a merged ES/GS ("NGG") stage that has no fixed-function equivalent in Vulkan's classic pipeline. Since September 2026 Kyty compiles that stage as a VK_EXT_mesh_shader mesh shader: DecodeFusedProgram() joins the front and back stage code into one instruction stream with an ordinary CFG edge between them, ShaderType::Mesh carries it through translation, and backend/spirv/spirvEmitterMesh.cpp emits the mesh entry point. The pipeline cache checks the guest's thread, vertex, primitive and LDS limits against the device's mesh-shader properties and stops with mesh shader exceeds host limits when they do not fit; if the extension is missing, that path is an EXIT_NOT_IMPLEMENTED.

One typed value IR

The current IR::Program derives from IR::ResourcePlan. The plan is the part the shader cache keeps for the lifetime of the run — stage, hash, descriptor sources, SRT reads, the values they depend on, the uniform-branch skeleton around them — while the program adds the blocks that exist only during translation and emission. Neither carries the old lane-mask mode or scalar-provenance structures:

…/ir/ShaderIR.h — ResourcePlan and Program
// Immutable runtime resource analysis retained by the shader cache.
struct ResourcePlan {
    ShaderType stage;  uint64_t shader_hash;
    uint32_t user_data_base, user_data_count = 64;
    std::list<Inst>               value_storage;
    std::vector<MemoryInfo>       memory_info;
    std::vector<DescriptorSource> descriptor_sources;
    std::vector<ResourceBlock>    control_flow;
    std::vector<uint32_t>         materialization_sources;
    std::vector<SrtRead>          srt_reads;
    std::vector<uint8_t>          clean_flat_slots;
    bool requires_specialization_memory, srt_plan_complete, resource_tracking_complete;
    ShaderInfo      info;
    UniformFillPlan uniform_fill;
};

struct Program : ResourcePlan {
    std::vector<std::unique_ptr<Block>> block_storage;
    BlockList        blocks;
    uint32_t         wave_size = 64, scratch_dwords = 0;
    bool             dispatcher_fallback = false;
    CFG::FailureKind cfg_failure_kind;
    std::string      fallback_reason;
    std::vector<BlockInfo>  block_info;
    std::vector<ExportInfo> export_info;
    std::vector<Value>      dynamic_reads;
    BindingLayout    bindings;
    std::optional<SpirvRequirements> spirv_requirements;
};

Translation initially permits register-like identities and control-flow joins. RewriteToSsa() establishes SSA form, then propagation, identity removal, and dead-code elimination simplify it. EliminateReadLane() removes cross-lane reads when a direct value is provably safe; if it rewrites anything, the simplification sequence runs again. Once emission is done the renderer keeps only a CompiledShaderInfo (stage, hash, wave size, ShaderInfo, BindingLayout) next to the plan; the blocks are discarded.

SRT planning, resources, and bindings

BuildSrtPlan() walks typed values to identify reachable shader-resource-table reads. Constant reads receive flattened offsets while genuinely dynamic reads stay explicit. TrackResources() then classifies buffers, images, samplers, access modes, formats, and sampled pairs.

Concrete resource data comes from MaterializeResources() (in ir/passes/ResourceMaterialization.cpp) reading current user data and guest memory into a ResourceSnapshot and a ResourceSpecialization. It runs in the renderer's pipeline cache on every draw, not inside the recompiler; CompileProgram() then calls ApplyResourceSpecialization() to bake those facts into the IR. It also skips resources that sit in uniform branches the current user data never takes, and detects whole-buffer fills from uniform stores so the renderer can replace a dispatch with a native clear. Compilation and per-draw resource state therefore remain separate concerns.

AllocateBindings() covers ordinary buffers/images/samplers plus emulator support bindings:

enum class DescriptorBindingKind : uint32_t {
    Buffers  = 0u,
    // … a dense range of typed image bindings (up to 64 images) …
    Samplers = FirstImageBinding + ImageBindingCount,   // 44
    Gds,
    BdaPagetable, FaultBuffer,
    FlattenedSrt, ShaderData,
    Count,                                              // 50
};

BdaPagetable and FaultBuffer support buffer-device-address translation and recoverable RDNA2 FLAT-access faults. FlattenedSrt and ShaderData expose data that the guest ABI expected in scalar registers or tables; PushData is 32 dwords of push constants, the first six of which a mesh draw uses for its own parameters. Finally, AnalyzeProgramRequirements() records the subgroup, derivative, LDS, scratch, and pixel-mask features emission must request.

Embedded vertex fetch

RDNA 2 has no conventional fixed-function vertex-input stage. A fetch prologue may load attributes into registers before the main vertex shader. When fetch_embedded is set, DetectEmbeddedVertexFetch() analyses the decoded instructions before translation and builds a Frontend::EmbeddedFetchPlan. That plan is passed through TranslateOptions::embedded_fetch, so translation emits the correct vertex-input operations directly; there is no later RewriteEmbeddedVertexFetches() pass.

Where the test weight is

ShaderRecompilerComputeTests.cpp is now about 1.43 MB and shaderCfgTests.cpp about 640 KB. The focused resource-tracking, resource-materialization (new, replacing the stage-runtime tests), scalar-tracing and vertex-metadata tests sit alongside them. The growth is useful evidence: shader behavior is specified most reliably by executable cases because a miscompile can produce only a visual error. Almost every shader commit in September 2026 lands with a new case in one of these two files.
