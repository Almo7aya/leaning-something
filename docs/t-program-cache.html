Appendix · C9

The program cache

Topics 15–17 describe the split between plan and SPIR-V. This page reads the one function that actually does it on every draw: ProgramCache::Get in pipelineCache.cpp.

Read

A draw arrives with a blob of RDNA 2, a hash, current user data, and stage input info. Get returns a handle the renderer can bind. Everything between those two sentences is this function.

How the stage is chosen

The template argument is the stage's input-info struct. Vertex input is special: if input_info.mesh.threads_num[0] != 0 the stage is ShaderType::Mesh, otherwise ShaderType::Vertex. Pixel and compute are unambiguous. That is the whole mesh-vs-vertex decision — merged ES/GS geometry stages arrive as vertex input with a non-zero mesh thread count, and from here they take the mesh path (DecodeFusedProgram, spirvEmitterMesh.cpp, VK_EXT_mesh_shader).

The lookup key

The program cache is keyed on stage, shader hash, user-data count, code size and a packed static-state blob from the input info — not on the current descriptors. Two draws of the same binary share an entry even when they bind different textures. What they do not share is the SPIR-V permutation:

src/graphics/host_gpu/renderer/pipeline/pipelineCache.cpp — ProgramCache::Get(), cache hit
if (entry != programs.end()) {
    EXIT_IF(!ShaderRecompiler::IR::MaterializeResources(
        entry->second.resource_plan, runtime, resources, specialization));
    if (const auto permutation = std::ranges::find_if(
            entry->second.permutations, [&](const Permutation& candidate) {
                return candidate.specialization == specialization
                    && /* push-constant placement matches */;
            });
        permutation != entry->second.permutations.end()) {
        input_info.stage = { .program = &permutation->program,
                             .resources = std::move(resources) };
        return permutation->handle;     // hot path: no Translate, no Compile
    }
}

On a hit, MaterializeResources still runs — user data changed. A failed read is EXIT_IF. If the resulting ResourceSpecialization matches a permutation already compiled, the function returns. That is the common case after the first few frames.

The two misses

A program miss means this binary has never been translated. TranslateProgram runs, ExtractResourcePlan keeps the immutable plan, then materialisation runs and the first permutation is compiled. A permutation miss means the plan is cached but this specialisation is new — only CompileProgram runs. Both miss paths end in CompilePermutation, which is the call that emits SPIR-V and a Vulkan shader module.

Mesh user-data base is 0; ordinary vertex user-data base is 8. Wave size and scratch dwords for mesh come from input_info.mesh, not from the generic vertex fields. If you are reading a mesh compile in the log, those are the numbers that fed it.

What the renderer receives

input_info.stage is a ShaderStageRuntime: a pointer to the compiled info plus the ResourceSnapshot just materialised. PrepareBindings reads the snapshot. Push-constant space is advanced with AdvancePushData so the next stage in the same draw does not collide; a mesh draw reserves six dwords of that space (PushData::MeshDrawDwordCount).

Three small surfaces next to it

These sit outside the graphics cache but show up in the same runs, so they belong on a page you read while debugging a title:

umtx wait / wake

UmtxOp in libKernel.cpp implements FreeBSD _umtx_op operations 2 (wait) and 3 (wake) on top of SyncOnAddress. A malformed timeout — negative seconds, or nanoseconds outside [0, 1e9) — sets errno to POSIX_EINVAL and returns −1. A valid timed wait is still EXIT (“not implemented”). Untimed wait and wake work. If a game hangs in a timed umtx, that is why.

DualSense light bar and triggers
src/libs/controller.cpp — PadSetLightBar / PadSetTriggerEffect
int KYTY_SYSV_ABI PadSetLightBar(int handle, const PadLightBarParam* param) {
    PRINT_NAME();
    if (handle != 1) return PAD_ERROR_INVALID_HANDLE;
    if (param == nullptr) return PAD_ERROR_INVALID_ARG;
    g_controller->SetLightBar(param->r, param->g, param->b);
    return OK;
}

Handle 1 is the only pad. The HIDAPI driver then drives the real DualSense. PadSetTriggerEffect is the same shape: validate handle and pointer, forward the struct, map a failed host call to PAD_ERROR_INVALID_ARG. The NIDs are RR4novUEENY (light bar) and 2JgFB2n9oUM (triggers) in libPad.cpp.

libCes — a whole module in one file

libCes.cpp is 10 KB of CP932 / Shift-JIS ↔ UTF-8 conversion, registered as LIB_VERSION("Ces", 1, "Ces", 1, 1). CesDecodeUtf8 is a textbook UTF-8 decoder with the replacement character 0xfffd on a truncated or invalid sequence. If you want a first HLE file to read that is not inlined inside libs.cpp, start here — then compare it to LibContentExport in topic 12.
